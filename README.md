# EE71 Monitor

[English version](README.en.md)

EE71 Monitor — неофициальное расширение для Chrome, Яндекс Браузера, Opera и Firefox, которое показывает состояние мобильного роутера **Alcatel EE71**: заряд батареи, мобильную сеть, сигнал, роуминг, состояние подключения и количество подключённых устройств.

Расширение использует системные данные домашней страницы роутера, доступные в локальной сети без авторизации в административной панели. Оно не изменяет настройки роутера и не отправляет полученную информацию во внешние сервисы.

Интерфейс доступен на русском и английском языках. По умолчанию язык выбирается по языку браузера.

Текущая версия: `1.4.0`.

> Проект не связан с Alcatel, TCL или оператором связи и не является их официальным программным обеспечением. Совместимость может зависеть от версии прошивки роутера.

## Возможности

- настраиваемый IP-адрес роутера с необязательным портом;
- автоматическое получение `_TclRequestVerificationKey` из `/pc/dist/build.js`;
- опрос `GetSystemStatus` через JSON-RPC;
- индикатор доступности роутера;
- заряд батареи в popup и на badge иконки вместе со знаком `%`; цвет текста badge задаётся явно и остаётся контрастным во всех состояниях;
- мобильная сеть, сигнал, роуминг, подключение и общее число клиентов;
- отдельные строки Wi‑Fi 2,4 и 5 ГГц: состояние диапазона, SSID и количество подключённых к нему устройств;
- пользовательский тип сети из `NetworkType`: `NA`, `2G`, `3G`, `3G+`, `4G` или `4G+`;
- фоновый опрос от 1 до 60 минут, по умолчанию каждые 5 минут;
- ручное обновление;
- настраиваемые одноразовые уведомления о низком и полном заряде;
- строгий компактный интерфейс в системном стиле Chrome/Android: desktop-popup имеет стабильную ширину 300 px и внутреннюю карточку 292 px с одинаковым скруглением в Chromium-браузерах, а на сенсорном устройстве адаптируется к доступной ширине;
- четыре выбираемых вида popup: «Сетка», «Акцент на сети», «Два кольца» и «Тёмная шапка»;
- цветные состояния: активные деления сигнала зелёные, Wi‑Fi голубой, подключение зелёное/красное/янтарное, роуминг янтарный;
- адаптивная страница настроек с вкладками «Общие», «Уведомления», «Интерфейс» и «О расширении»;
- информационная вкладка с текущей версией, описанием возможностей, политикой конфиденциальности, GitHub-ссылками и копирайтом;
- автоматическая светлая/тёмная тема;
- полностью локальная работа без внешних серверов.

## Установка в Chrome и Opera

1. Выполните `node scripts/build.mjs`, если папка `build/chrome` ещё не создана или исходный код изменился.
2. Откройте `chrome://extensions/` в Chrome или `opera://extensions/` в Opera.
3. Включите «Режим разработчика».
4. Нажмите «Загрузить распакованное расширение».
5. Выберите папку `build/chrome` из этого проекта.
6. Откройте popup расширения, перейдите в настройки и нажмите «Сохранить и проверить».
7. Разрешите доступ к указанному IP-адресу роутера.

Для Chrome и Opera используется Manifest V3 только с `background.service_worker`, поэтому предупреждение о `background.scripts` не появляется. Для Opera используется готовая папка `build/chrome`.

## Установка в Яндекс Браузер

1. Выполните `node scripts/build.mjs`, если папка `build/yandex` ещё не создана или исходный код изменился.
2. Откройте `browser://extensions/` или `chrome://extensions/`.
3. Включите «Режим разработчика».
4. Нажмите «Загрузить распакованное расширение».
5. Выберите папку `build/yandex` из этого проекта.
6. Откройте настройки расширения, нажмите «Сохранить и проверить» и подтвердите доступ к адресу роутера.

Яндекс Браузер использует Chromium-совместимый Manifest V3 и отдельную сборку с `background.service_worker`. Локальное распакованное расширение предназначено для разработки: браузер может отключить его после перезапуска. Для постоянного распространения потребуется публикация в поддерживаемом магазине расширений.

## Установка в Firefox для разработки

1. Выполните `node scripts/build.mjs`, если папка `build/firefox` ещё не создана или исходный код изменился.
2. Откройте `about:debugging#/runtime/this-firefox`.
3. Нажмите «Загрузить временное дополнение».
4. Выберите файл `build/firefox/manifest.json`.
5. Откройте настройки дополнения и сохраните адрес роутера.
6. Подтвердите доступ к указанному IP-адресу.

Временное дополнение удаляется после перезапуска Firefox. Для постоянной установки XPI должен быть подписан через Mozilla Add-ons.

Для Firefox используется отдельный манифест только с `background.scripts`. Исходный общий код находится в папке `extension`, а готовые для загрузки варианты создаются командой:

```bash
node scripts/build.mjs
```

Минимальные версии: Chrome 121 и Firefox 142. Yandex-сборка проверена на Яндекс Браузере 26.6.1.1083.

## Настройка

Адрес по умолчанию:

```text
192.168.1.1
```

Можно указать порт:

```text
192.168.1.1:8080
```

Пути и параметры запроса в поле адреса не допускаются.

При первом сохранении браузер показывает системный запрос разрешения. Расширение запрашивает доступ только к введённому IP/имени хоста. WebExtensions match pattern не позволяет ограничить host-permission конкретным портом, но сами запросы выполняются только по полностью настроенному адресу, включая порт.

## Как выполняется запрос

1. Расширение загружает `http://[IP]/pc/dist/build.js`.
2. Из JavaScript извлекается статический `_TclRequestVerificationKey`.
3. Если в коде присутствует статическое присваивание `_TclRequestVerificationToken`, оно также используется. На проверенном EE71 токен формируется из авторизационной cookie и для чтения статуса не нужен.
4. Для `POST /jrd/webapi` добавляется `Referer: http://[IP]/` через узкое динамическое правило `declarativeNetRequest`. Роутер требует этот заголовок и без него возвращает `Authentication Failure`.
5. Отправляется `GetSystemStatus`, результат сохраняется локально и отображается в popup.

Ключ и найденный статический токен кэшируются для выбранного базового адреса. После изменения настроек кэш сбрасывается. При HTTP- или JSON-RPC-ошибке API расширение один раз принудительно перечитывает `build.js` и повторяет запрос. Тайм-аут каждого сетевого запроса — 12 секунд; параллельные обновления объединяются в один выполняющийся запрос.

Запросы выполняются с `credentials: omit`: авторизационные cookie административной панели не используются. Динамическое правило `Referer` действует только на `POST http://[IP]/jrd/webapi` для выбранного адреса.

## Уведомления и локализация

- порог низкого заряда по умолчанию — 20%, допустимый диапазон — 1–100%;
- уведомление срабатывает один раз при заряде на пороге или ниже и снова разрешается после подъёма заряда выше порога;
- уведомление о полном заряде по умолчанию включено и срабатывает только при наблюдаемом переходе с уровня ниже 100% на 100%;
- первое полученное значение 100% и повторные проверки при постоянных 100% уведомление не вызывают; после падения ниже 100% новый подъём до 100% снова вызывает его;
- оба типа уведомлений можно отключать независимо, а русский и английский тексты можно менять отдельно;
- на странице уведомлений показываются текстовые поля только фактически выбранного языка с общим заголовком «Текст уведомления»; для режима «Автоматически» рядом с выбором языка показывается фактически используемый язык браузера, а при ручном выборе эта подсказка скрывается;
- `{level}` заменяется фактическим процентом заряда;
- язык `Автоматически` выбирает русский для языка браузера `ru`, для остальных языков используется английский;
- интервал опроса ограничен диапазоном 1–60 минут, значение по умолчанию — 5 минут;
- состояние и настройки хранятся локально через `storage.local`.

## Варианты popup и тип сети

Вкладка «Интерфейс» содержит четыре визуальные радиокарточки с детерминированными SVG-превью без CSS-псевдоэлементов. Превью варианта «Два кольца» показывает две полные окружности рядом. По умолчанию используется «Сетка». Выбор сохраняется как `popupStyle` и применяется при открытии popup без дополнительного запроса к роутеру. Вариант «Два кольца» показывает рядом увеличенные диаграммы сигнала и батареи диаметром 106 px. Все варианты показывают одинаковые данные и отличаются только компоновкой.

Пользовательские сообщения сетевых ошибок описывают загрузку «данных» и не показывают внутреннее имя `build.js`. Сам путь `/pc/dist/build.js` остаётся частью технического протокола получения ключа.

Каждый вариант содержит компактный блок диапазонов Wi‑Fi. Для 2,4 ГГц используются `WlanState_2g`, `Ssid_2g`, `curr_num_2g`; для 5 ГГц — `WlanState_5g`, `Ssid_5g`, `curr_num_5g`. Полный SSID сохраняется в подсказке, если строка не помещается.

`NetworkType` преобразуется так: `0 → NA`; `1`, `2`, `11 → 2G`; `3`, `4`, `5 → 3G`; `6`, `7 → 3G+`; `8 → 4G`; `9 → 4G+`. Неизвестный целочисленный код отображается как «Тип N» или `Type N`, отсутствующее значение — как `—`.

## Разрешения

| Разрешение | Назначение |
|---|---|
| `storage` | Локальное хранение настроек и последнего статуса |
| `alarms` | Периодический фоновый опрос |
| `notifications` | Предупреждения о низком и полном заряде |
| `declarativeNetRequestWithHostAccess` | Установка требуемого роутером `Referer` только для `POST /jrd/webapi` |
| optional `http://*/*` | Динамический запрос доступа к конкретному IP/имени хоста, введённому пользователем; браузерное разрешение не ограничивается портом |

Расширение не собирает и не передаёт данные на внешние серверы.
